# 준비물과 정할 값

> **이 문서는 언제 보나요?** 설치를 시작하기 전에 한 번. 여기서 정한 계정·도메인·IP 값을 뒤의 모든 문서가 씁니다. 설치 중 "이 값은 뭐였지?" 할 때도 이 문서의 표를 봅니다.

---

## 1. 준비물

사는 장비는 없습니다. 계정 세 개(AWS · Claude Console · 도메인을 관리하는 가비아)와 내 맥이 필요하며, 기본 설치에서 **AI 서버와 Langfuse 서버로 EC2 두 대**를 빌립니다.

| 준비물 | 용도 | 확인 |
|---|---|---|
| AWS 콘솔 계정 | K3s·Langfuse용 EC2 두 대, 각각의 보안 그룹·탄력적 IP·디스크 스냅샷, 외부 호스트 경보 만들기 | 딸기로 운영 서버가 있는 계정을 씁니다 |
| Claude Console 계정 | Claude API 키 발급, 요금 결제, 지출 한도 | <https://platform.claude.com> 에서 회사 메일로 만듭니다. 결제할 카드가 필요합니다([Claude API 문서](../02-Claude-API/01-Claude-API-키와-모델.md)) |
| 딸기로 도메인의 DNS 관리 권한 | AI·Langfuse 서버용 하위 도메인 두 개 추가 | 가비아 계정 |
| 내 맥 | 저장소 받기, 이미지 빌드, SSH 접속 | Docker Desktop, `git`, `ssh`, `rsync` |

- **AWS 콘솔 계정**: EC2·EBS·CloudWatch·SNS·CloudFormation 권한을 확인합니다([계정과 비밀값 관리](../../../ddalgiro-guide/docs/00-개요/04-계정과-비밀값-관리.md)).

## 2. 미리 받아 둘 계정·권한

| 무엇 | 어디서 | 언제 쓰나 |
|---|---|---|
| AI 서버용 도메인 이름 | 딸기로 도메인의 DNS 관리 화면(문서의 예시는 `ai.example.com`) | [외부 공개](../05-외부-공개/01-보안-그룹과-HTTPS.md). DNS 레코드를 추가할 수 있는 권한이 필요합니다 |
| Langfuse 서버용 도메인 이름 | 같은 DNS 관리 화면(문서의 예시는 `langfuse.example.com`) | [별도 서버 설치](../07-운영/02-모니터링과-AI-추적.md#4-langfuse-별도-서버-준비). 이 서버의 탄력적 IP를 가리키는 A 레코드가 필요합니다 |
| 회사 SMTP와 운영 알림 수신자 | SMTP 관리자에게 STARTTLS 지원 `호스트:587`·발신 권한·인증 값을 받음 | [운영 알림](../07-운영/02-모니터링과-AI-추적.md#2-ai-서버에-지표알림-올리기). 비밀값은 Secret에만 보관합니다 |
| 딸기로 백엔드 서버의 공인 IP | AWS 콘솔의 EC2 → 운영 서버의 탄력적 IP | 접근 허용 목록(`ALLOW_IP_1`)과 보안 그룹의 443 규칙 |
| 내가 접속하는 곳의 공인 IP | 그 자리에서 <https://checkip.amazonaws.com> 을 열면 보입니다 | 보안 그룹의 SSH(22) 규칙. 사무실처럼 IP가 잘 바뀌지 않는 곳에서 접속합니다 |
| Claude API 키 | Claude Console의 API 키 화면 | [Claude API 문서 3장](../02-Claude-API/01-Claude-API-키와-모델.md#3-api-키-만들기)에서 만들어 [플랫폼 2장](../03-플랫폼/01-데이터베이스-임베딩-LLM-게이트웨이.md#2-비밀값-만들기)에서 넣습니다 |
| 네이버 개발자 센터 애플리케이션 | <https://developers.naver.com> → 애플리케이션 등록 → 사용 API에 **검색**과 **데이터랩(검색어 트렌드)** 추가 | [트렌드 분석](../04-에이전트/02-트렌드-분석-추천.md)의 수집. Client ID와 Client Secret을 받습니다 |
| (선택) 인스타그램 해시태그 조회 권한 | 인스타그램 **비즈니스·크리에이터 계정** + 그 계정과 이은 페이스북 페이지 + 개발자 앱 | [인스타그램 수집](../04-에이전트/02-트렌드-분석-추천.md#5-수집-출처-넓히기--인스타그램rss크롤링). 계정 번호(IG User ID)와 접근 토큰을 받습니다 |
| (선택) 읽을 RSS·웹 피드 목록 | [추천 목록](../04-에이전트/04-수집-출처-고르기와-추천-목록.md#2-추천-목록)에서 고릅니다. **사이트마다 약관이 자동 수집을 허용하는지** 확인한 것만 | [RSS·웹 피드 수집](../04-에이전트/02-트렌드-분석-추천.md#5-수집-출처-넓히기--인스타그램rss크롤링). 없으면 피드 수집만 건너뜁니다 |

- **딸기로 백엔드 서버의 공인 IP**: ⚠️ AI 서버는 이 IP만 들여보내므로, IP가 바뀌면 AI 호출이 모두 막힙니다 — 바뀌면 [허용 IP를 바꿉니다](../05-외부-공개/01-보안-그룹과-HTTPS.md#허용-ip를-바꿀-때).
- **네이버 개발자 센터 애플리케이션**: 없어도 샘플 데이터로 전체 흐름은 확인할 수 있습니다.
- **(선택) 인스타그램 해시태그 조회 권한**: 개발자 앱은 <https://developers.facebook.com>에 등록한 앱입니다. 앱 심사에서 **Instagram Public Content Access** 기능과 `instagram_basic` 권한을 받아야 합니다(2026-11-15 Meta 문서 기준). 심사에 시간이 걸리므로 먼저 신청해 둡니다. 없으면 인스타그램 수집만 건너뜁니다.

## 3. 정할 값

아래 표를 채웁니다. **예시 값**으로 문서를 썼으므로, 내 값이 다르면 명령의 해당 부분을 바꿔 넣습니다. 항목 뒤 괄호의 영문 대문자 이름은 `site.env`에 적는 값의 이름입니다.

| 항목 | 예시 값 | 정하는 방법 |
|---|---|---|
| AWS 리전 | 아시아 태평양(서울) `ap-northeast-2` | 딸기로 운영 서버와 같은 리전 |
| AI 인스턴스 이름 | `ddalgiro-ai` | AWS 콘솔에서 알아볼 이름 |
| AI 인스턴스 유형 · 디스크 | `t3.xlarge`(4 vCPU · 16GiB) · gp3 100GiB | [K3s 서버 문서 1장](../01-K3s-서버/01-EC2-인스턴스와-K3s.md#1-ec2-인스턴스-만들기)의 표 |
| Langfuse 인스턴스 이름 · 사양 | `ddalgiro-observe`, **`m7i.xlarge`(4 vCPU·16GiB) · gp3 100GiB · Ubuntu 24.04 x86_64** | [관측 서버 설치 표](../07-운영/02-모니터링과-AI-추적.md#4-1-자원접근). 기본 설치이며 K3s는 올리지 않습니다 |
| Langfuse 키 페어 · SSH 이름 | `~/.ssh/ddalgiro-observe.pem` · `ddalgiro-observe` | 별도 키 페어와 내 맥 SSH 접속 이름 |
| Langfuse 탄력적 IP · 도메인 | `203.0.113.40` · `langfuse.example.com` | 별도 인스턴스에 IP 할당, DNS A 레코드 연결 |
| Langfuse 연결 설정 | `LANGFUSE_ENABLED=true`, `LANGFUSE_BASE_URL=https://langfuse.example.com` | 실제 도메인으로 바꿔 `site.env`에 저장 |
| 키 페어 파일 | `~/.ssh/ddalgiro-ai.pem` | 인스턴스를 만들 때 새로 받습니다 |
| K3s 서버의 탄력적 IP | `203.0.113.20` | 인스턴스를 만든 뒤 할당받습니다. 서버를 껐다 켜도 바뀌지 않는 공인 IP입니다 |
| SSH 접속 이름 | `ddalgiro-ai` | 내 맥의 `~/.ssh/config`에 붙이는 별칭. 문서의 `ssh ddalgiro-ai`가 이 이름입니다 |
| 서버 계정 이름 | `ubuntu` | 우분투 이미지의 기본 계정 |
| AI 서버 도메인 (`AI_DOMAIN`) | `ai.example.com` | 2장에서 정한 하위 도메인 |
| 인증서 안내 메일 (`ACME_EMAIL`) | `you@example.com` | 실제로 받는 메일 주소. ⚠️ `example.com` 주소는 발급 기관이 거절합니다 |
| 백엔드 서버 공인 IP (`ALLOW_IP_1`) | `203.0.113.10` | 2장에서 확인. `site.env`에는 끝에 `/32`를 붙여 적습니다 |
| 확인용 공인 IP (`ALLOW_IP_2`) | `203.0.113.30` (없으면 백엔드와 같은 값) | 설치 중 바깥에서 시험할 곳의 IP |
| 대화 모델 (`CHAT_FAST_MODEL` · `CHAT_SMART_MODEL`) | `claude-haiku-5-5` · `claude-sonnet-5-5` | [Claude API 문서 2장](../02-Claude-API/01-Claude-API-키와-모델.md#2-어떤-모델을-쓰나). 견본 값 그대로 시작합니다 |

- **Langfuse 연결 설정**: 프로젝트 키는 `site.env`가 아니라 K3s Secret `ai-app/agent-secret`에 넣습니다.
- **확인용 공인 IP (`ALLOW_IP_2`)**: SSH로 접속하는 곳(2장의 "내가 접속하는 곳")과 같아도 됩니다. 휴대폰 테더링은 IP가 자주 바뀌어 맞지 않습니다.

### 값 파일 만들기

내 맥에서 이 저장소 폴더로 가서 값 파일을 만들고 위 표의 값으로 고칩니다.

```bash
cd ~/workspace/workspace-vscode/ddalgiro-ai-agent
cp site.env.example site.env
open -e site.env
```

- 첫 줄은 저장소 폴더로 이동합니다(경로가 다르면 바꿉니다).
- 둘째 줄은 견본을 복사합니다. `site.env`는 git에 올라가지 않습니다.
- 셋째 줄은 텍스트 편집기로 엽니다. 각 항목의 뜻은 파일 안의 설명에 있습니다. `CLUSTER_ISSUER`는 처음에는 `letsencrypt-staging`으로 둡니다.
- 새 설치의 `LANGFUSE_ENABLED`는 **true**를 유지하고 `LANGFUSE_BASE_URL`을 실제 도메인으로 바꿉니다. [전체 설치 순서](01-전체-구성-한눈에-보기.md#9-따라-하는-순서)에 따라 별도 서버를 먼저 만들고, 에이전트 배포 전에 프로젝트 키를 넣습니다.
- 맨 아래의 DGX Spark 세 줄은 주석(`#`)인 채로 둡니다. [추후 도입](../08-추후-도입/01-DGX-Spark-도입.md) 때만 씁니다.

## 4. 비밀값은 어디에 두나

비밀번호와 키는 **문서·채팅·git에 적지 않습니다.** 만들어지는 곳과 두는 곳만 정리합니다.

| 값 | 만드는 곳 | 보관 위치 | 쓰는 곳 |
|---|---|---|---|
| EC2 키 페어(`ddalgiro-ai.pem`·`ddalgiro-observe.pem`) | AWS 콘솔(인스턴스를 만들 때 한 번만 내려받음) | 내 맥의 `~/.ssh/`, 사본은 딸기로의 비밀값 보관 매체 | 각 서버 SSH 접속. ⚠️ 잃으면 서버에 접속할 수 없습니다 |
| `ANTHROPIC_API_KEY` (Claude API 키) | Claude Console | K3s Secret `ai-llm/litellm-secret` | LiteLLM → Claude API. ⚠️ 새면 남이 우리 요금으로 모델을 씁니다 |
| DB 비밀번호 3개 | `create-secrets.sh`가 무작위 생성 | K3s Secret `ai-data/postgres-secret` | PostgreSQL, 백업 |
| `LITELLM_MASTER_KEY` (게이트웨이 키) | 〃 | K3s Secret `ai-llm/litellm-secret`, `ai-app/agent-secret`(여기서는 이름이 `LITELLM_API_KEY`) | 에이전트 → LiteLLM |
| `AI_API_KEY` (AI 서버를 부르는 키) | 〃 | K3s Secret `ai-app/agent-secret`, 백엔드 서버 `/app/security/secrets.yml` | 백엔드 → agent-api |
| 네이버 Client ID·Secret | 네이버 개발자 센터 | K3s Secret `ai-app/agent-secret` | 수집 작업 |
| 인스타그램 계정 번호·접근 토큰 | Meta 개발자 화면 | K3s Secret `ai-app/agent-secret` (`create-secrets.sh --instagram`) | 인스타그램 수집 작업. 토큰은 기한이 있어 만료 전에 다시 넣습니다 |
| SMTP 발신·수신 주소·인증 값 | 회사 SMTP 관리자 | K3s Secret `ai-observe/alertmanager-config` | 장애·해제 이메일. `scripts/observability/create-secrets.py --alerts`로 입력 |
| Langfuse 프로젝트 공개·비밀 키 | `scripts/langfuse/init-env.py`가 생성(또는 Langfuse 화면의 프로젝트 설정) | 별도 서버 `deploy/langfuse/.env`, K3s Secret `ai-app/agent-secret` | AI 처리 추적. `scripts/observability/create-secrets.py --langfuse`로 입력 |
| 별도 Langfuse DB·암호화·초기 관리자 값 | `scripts/langfuse/init-env.py`가 생성 | 별도 서버 `deploy/langfuse/.env`(600), 암호화된 보관 매체 | 별도 Compose 부품. `.env`를 덮어쓰지 않음 |
| (Langflow를 넣었을 때) Langflow의 암호화 열쇠 | `create-secrets.sh --langflow`가 무작위 생성(44자 base64) | K3s Secret `ai-app/langflow-secret` | Langflow가 전역 변수를 암호화. ⚠️ 바뀌면 Langflow에 저장한 키를 풀 수 없습니다 |
| (〃) Langflow 관리자(`admin`) 비밀번호 | 〃 | K3s Secret `ai-app/langflow-secret`, 딸기로의 비밀값 보관 매체 | Langflow 로그인. 첫 기동 때만 Secret 값으로 계정을 만듭니다 |
| (〃) Langflow 전용 게이트웨이 키 | `create-secrets.sh --langflow-key`가 만들어 한 번 보여 줌 | Langflow 화면의 전역 변수(암호화 저장), 게이트웨이의 `litellm` DB | Langflow → LiteLLM. 30일 한도가 걸려 있습니다 |

- **Secret**: 쿠버네티스가 비밀값을 보관하는 자원입니다. 파드는 이 값을 환경 변수로 받습니다.
- **DB 비밀번호 3개**: 게이트웨이·에이전트용 비밀번호는 `litellm-secret`·`agent-secret`의 `DATABASE_URL`에도 들어 있습니다.
- 백엔드 쪽 보관 규칙은 [계정과 비밀값 관리](../../../ddalgiro-guide/docs/00-개요/04-계정과-비밀값-관리.md)를 따릅니다.
- ⚠️ K3s 서버의 디스크가 망가지면 Secret도 함께 사라집니다. [운영 문서](../07-운영/01-점검-백업-문제-해결.md#4-3-비밀값-따로-보관하기)의 절차로 Secret도 따로 보관합니다.

## 5. 버전 고정표

기준일 **2026-11-15**(운영 지표·알림과 별도 Langfuse 행은 2026-11-16). 문서의 명령과 매니페스트는 이 버전으로 썼습니다. 버전을 올릴 때는 이 표를 먼저 고칩니다.

| 부품 | 버전 | 정해진 곳 | 이 저장소에서 확인한 것 |
|---|---|---|---|
| K3s 서버 | AWS EC2 `t3.xlarge`(x86_64) · gp3 100GiB · 서울 리전 | AWS 콘솔 | **AWS에서는 확인하지 못함** — 실제로 만들어 보지 않았습니다 |
| K3s 서버 OS | Ubuntu Server 24.04 LTS (EC2 이미지) | 인스턴스를 만들 때 | 실제 인스턴스에서 확인하지 못함 |
| K3s | `v1.37.2+k3s1` (stable 채널) | 설치 명령 | 운영 지표·알림을 뺀 매니페스트 11개를 `v1.37.2+k3s1`(k3d)에 올려 확인 |
| Traefik | v3 (K3s 내장) | K3s | 접근 제한·경로·HTTPS 동작 확인(k3d) |
| cert-manager | `v1.21.3` | 설치 명령 | 설치와 발급처 등록 요청까지 확인. 실제 인증서 발급은 확인하지 못함(공개 도메인 필요) |
| PostgreSQL + pgvector | `pgvector/pgvector:0.8.7-pg18` | `k8s/10-postgres.yaml` | 첫 기동·확장·백업 확인. 실제 서버의 복원·작업 중지/재시작은 확인 필요 |

- **K3s 서버**: 보안 그룹·탄력적 IP·디스크 스냅샷 절차도 AWS에서 확인하지 못했습니다. 사양의 근거는 내 맥의 시험용 클러스터(메모리 16GB · CPU 4개 제한, arm64)에서 잰 값입니다([이 사양으로 충분한가](../01-K3s-서버/01-EC2-인스턴스와-K3s.md#이-사양으로-충분한가)).
- **K3s**: 올린 클러스터는 arm64, 노드 이름 `k3s-ai`입니다. 운영 지표·알림의 확인은 표의 운영 지표·알림 행에 따로 적었습니다. 접근 제한의 동작(허용 IP·경로·키)은 `v1.36.4+k3s1`에서 확인한 것입니다.
- **PostgreSQL + pgvector**: 로컬 Docker에서 기존 스키마 갱신·복원 후 전체 행/시퀀스/소유권 일치·복원 실패 시 전체 롤백을 확인했습니다. 이전 구조의 DB에 현재 정의를 두 번 적용해 공급 조건이 메뉴 단위로 옮겨지고 기존 행이 남는 것도 확인했습니다.
- **임베딩 서버 (TEI)**: arm64에서 메뉴 5,010건을 임베딩했고 실제 메모리는 약 2.7GB였습니다. x86_64용은 속도·메모리가 다를 수 있습니다.
- **LiteLLM**: 현재 모델 표를 이 이미지에 넣고 가짜 Claude 서버로 확인한 것은 주소 `/v1/messages`, 모델 ID, 출력 한도 16000, `temperature` 제거, 양식 강제 요청, 그 요청이 거절될 때의 대체 경로, `drop_params`를 끄면 실패, 생각 깊이(`output_config`의 `effort`)가 요청에 실리는 것입니다.
- **Langflow (선택)**: API로 확인한 것은 관리자 로그인, 로그인하지 않은 가입 거절, 전역 변수, 흐름(Chat Input → Prompt Template → OpenAI 블록, API Request → Parser) 실행, 재시작 뒤 흐름·변수 보존, 막아 둔 내부 주소·새 블록·파이썬 실행 블록의 거절, 전용 게이트웨이 키입니다. 메모리는 약 1.3GiB였습니다. 암호화 열쇠는 44자 base64여야 합니다(16진수면 변수 저장이 실패).
- **대화 모델**: 한국어 조건 뽑기·브리핑 품질, 응답 시간, 실제 요금도 재지 못했습니다.
- **에이전트**: 그 밖의 라이브러리 버전은 langchain-openai 1.8.0, psycopg 3.3.9, pgvector 0.5.1입니다.
  - LLM 연결 시험의 로컬 모델은 Qwen2.5·bge-m3이며 Claude API로는 돌리지 않았습니다. 작은 로컬 모델에서는 식이 조건 1건(글루텐프리를 비건으로 뽑음)이 실행에 따라 실패합니다(10~11개 통과).
  - amd64 이미지 빌드·API 준비 상태/인증·기존 DB 갱신·6시간 수집 매니페스트를 확인했습니다.
  - **실제 자료로 확인하지 못한 것**: 실제 다중 출처 백테스팅(동결 자료·정점 정답 필요; 데이터랩 탐색은 네이버 키 필요), 인스타그램 수집(계정·토큰 필요 — 가짜 응답으로만 시험), RSS 수집의 DB 저장(피드 읽기와 점검 명령은 실제 피드 25개 주소로 확인, 약관은 미확인).
- **운영 지표·알림**: 수집기 3개는 Node Exporter 1.12.1, kube-state-metrics 2.20.0, Blackbox Exporter 0.29.1입니다. 임시 K3s에 올려 파드와 수집 대상 9개가 정상인 것, 가짜 SMTP로 경보 발생·해제 메일이 오는 것을 확인했습니다.
- **별도 Langfuse**: 함께 쓰는 ClickHouse는 26.3.62.3이고, PostgreSQL 17·Redis 7·MinIO·Caddy는 고정 다이제스트입니다. 비수집 확인은 DB 초기화·프로젝트 인증·SDK 수신·v4 관측 조회로 했고, 병렬 추적·실패 시 업무 유지도 확인했습니다.
- **인스타그램 Graph API**: 확인한 한도는 7일에 해시태그 30개, 최근 24시간, 한 쪽 50건입니다.

> **대화 모델에 대해.** 모델 ID는 Anthropic이 새 모델을 내면 바뀌고, 옛 모델은 예고한 뒤 종료됩니다. 바꾸는 방법은 [Claude API 문서 7장](../02-Claude-API/01-Claude-API-키와-모델.md#7-모델을-바꿀-때)에 있습니다. 한국어 운영 품질은 아직 재지 않았으므로, 운영 전에 [평가와 합격 기준](../02-Claude-API/01-Claude-API-키와-모델.md#6-운영-전-평가와-합격-기준)으로 확인합니다. 추후 도입할 DGX Spark 쪽 부품(vLLM·로컬 모델)의 버전은 [그 문서](../08-추후-도입/01-DGX-Spark-도입.md#11-버전)에 따로 있습니다.
