# EC2 인스턴스와 K3s

> **이 문서는 언제 보나요?** AWS에 AI용 서버(EC2 인스턴스) 한 대를 만들고 쿠버네티스(K3s)를 올릴 때. 끝나면 서버에서 `kubectl get nodes`가 `Ready`를 보여 줍니다.
>
> 먼저 [준비물과 정할 값](../00-개요/02-준비물과-정할-값.md)을 마칩니다. 예시 값: 인스턴스 이름·SSH 접속 이름 `ddalgiro-ai`, 탄력적 IP `203.0.113.20`, 계정 `ubuntu`, 내가 접속하는 곳의 공인 IP `203.0.113.30`.
>
> ⚠️ 이 문서의 AWS 콘솔 절차와 서버 설정은 실제 계정·인스턴스에서 확인하지 못했습니다. 콘솔 화면의 이름은 AWS가 바꿀 수 있습니다. K3s 설치 뒤의 매니페스트 동작과 사양의 근거는 내 맥의 시험용 클러스터에서 확인했습니다([버전 고정표](../00-개요/02-준비물과-정할-값.md#5-버전-고정표)).

---

## 1. EC2 인스턴스 만들기

딸기로 운영 서버를 만들 때와 같은 방법입니다([빈 서버에서 전체 구축 1장](../../../ddalgiro-guide/docs/03-서버/01-빈-서버에서-전체-구축.md#1-aws-에-서버ec2-만들기)). 값만 다릅니다.

1. AWS 콘솔 → 오른쪽 위 지역을 **아시아 태평양(서울) ap-northeast-2**로 맞춥니다.
2. **EC2 → 인스턴스 시작**을 누르고 아래처럼 고릅니다.

   | 칸 | 값 | 이유 |
   |---|---|---|
   | 이름 | `ddalgiro-ai` | 운영 서버와 구분 |
   | OS 이미지 | **Ubuntu Server 24.04 LTS** (64비트 x86) | 이 가이드의 명령과 컨테이너 이미지가 우분투·x86 기준입니다 |
   | 인스턴스 유형 | `t3.xlarge` (4 vCPU · 메모리 16GiB) | 부품들이 요청하는 CPU가 합쳐 약 3.3코어, 실제로 쓰는 메모리가 5GiB쯤입니다 |
   | 키 페어 | 새로 만들기 → 이름 `ddalgiro-ai` → `.pem` 내려받기 | 서버 열쇠. **한 번만 내려받을 수 있고, 잃으면 접속할 수 없습니다** |
   | 스토리지 | **100GiB**, gp3 | DB·임베딩 모델(약 2.3GB)·컨테이너 이미지·DB 백업 파일·운영 지표(최대 8GB) |
   | 고급 세부 정보 → 종료 방지 | 활성화 | 실수로 인스턴스를 지우지 않게 |

   - **인스턴스 유형**: 한 단계 아래(2 vCPU · 8GiB)에는 올라가지 않습니다([근거](#이-사양으로-충분한가)).

3. 같은 화면의 **네트워크 설정 → 보안 그룹 만들기**에서 들어올 수 있는 문을 정합니다. 이름은 `ddalgiro-ai-sg`로 합니다.

   | 포트 | 누가 | 이유 |
   |---|---|---|
   | 22 (SSH) | **내 IP 하나** (`203.0.113.30/32`) | 서버 관리. ❌ `0.0.0.0/0`(아무 곳)으로 열지 않습니다 |

   - **보안 그룹**: 인스턴스 앞에서 "어느 IP가 어느 포트로 들어올 수 있는지" 정하는 AWS의 방화벽입니다. 적지 않은 포트는 모두 막힙니다.
   - 80·443은 지금 열지 않습니다. 에이전트를 올린 뒤 [외부 공개](../05-외부-공개/01-보안-그룹과-HTTPS.md) 단계에서 엽니다.
   - 나가는 쪽(아웃바운드)은 기본값(모두 허용)으로 둡니다. 서버가 Claude API·네이버 API·이미지 저장소로 나가야 합니다.

4. **인스턴스 시작**을 누릅니다.
5. **탄력적 IP**를 붙입니다: EC2 → 탄력적 IP → 탄력적 IP 주소 할당 → 만든 주소를 고르고 작업 → 탄력적 IP 주소 연결 → 인스턴스 `ddalgiro-ai`.

   - **탄력적 IP**: 서버를 껐다 켜도 바뀌지 않는 공인 IP입니다. 붙이지 않으면 켤 때마다 IP가 바뀌어 도메인이 서버를 잃습니다.
   - 받은 주소를 [정할 값 표](../00-개요/02-준비물과-정할-값.md#3-정할-값)에 적어 둡니다.

⚠️ 콘솔의 **인스턴스 종료(terminate)**는 서버와 디스크를 지웁니다. 잠시 끌 때는 **인스턴스 중지(stop)**를 씁니다.

### 이 사양으로 충분한가

초기 시제품을 올릴 기본 사양으로 잡았습니다. 내 맥의 시험용 클러스터(k3d, K3s `v1.37.2+k3s1`)를 **메모리 16GB · CPU 4개**로 묶고 이 저장소의 매니페스트를 올린 결과는 아래와 같습니다(2026-11-15). 카탈로그는 지어낸 메뉴 5,010건을 넣었고, Claude API는 바로 답하는 가짜 서버로 바꿔 **서버 쪽에서 걸리는 시간만** 쟀습니다. 실제 EC2의 처리량과 Claude API를 포함한 응답 시간은 아직 확인하지 못했습니다.

| 항목 | 잰 값 | 뜻 |
|---|---|---|
| 메모리(실제 사용) | 전체 약 5.0GiB | 16GB의 3분의 1. 남는 메모리는 파일 캐시(모델·DB 파일)와 늘어날 자료가 씁니다 |
| CPU 요청량 | 3.1코어. 운영 지표·알림 0.225를 더한 기본 설치는 약 3.3코어 | 4 vCPU에는 들어가고 2 vCPU에는 파드가 뜨지 못합니다(`Insufficient cpu`) |
| 대기 중 CPU 사용 | 약 0.13코어 | 평소에는 거의 쉬고 있습니다 |
| 문의 한 줄 임베딩 | 37ms (CPU를 1개 분량으로 줄이면 200ms) | 추천 한 건에 한 번 |
| 자연어 추천 한 건의 서버 쪽 시간 | 0.07초, 동시 4건이면 0.17초 (CPU 1개 분량: 0.12초 · 0.7초) | 지연 없는 가짜 Claude 서버로 잰 값입니다. 실제 모델 대기와 EC2 처리 시간을 합쳐 다시 재야 합니다 |
| 처리량 | 초당 약 28건 (CPU 1개 분량: 약 6.5건) | 직원 몇 명이 쓰는 양보다 훨씬 큽니다 |
| 메뉴 임베딩(새벽 작업) | 초당 11건 — 1만 건에 15분 (CPU 1개 분량: 초당 약 2건 — 1만 건에 약 100분) | 평소에는 새로 넣거나 바뀐 메뉴만 처리합니다 |
| 디스크 | 약 7GB — 컨테이너 이미지 4.1, 임베딩 모델 2.2, DB 0.2, DB 백업 0.03 (우분투 자체는 별도) | 100GB의 10분의 1 |

- **메모리(실제 사용)**: 전체 약 5.0GiB는 임베딩 서버 2.7, 게이트웨이 0.7~0.8, DB 0.1~0.4, 에이전트 0.1~0.2, K3s와 그 부속 약 1.2로 나뉩니다.
- **CPU 요청량**: 3.1코어는 임베딩 서버 2, DB 0.5, 게이트웨이·에이전트 0.2씩, K3s 부속 0.2입니다. 정기 작업은 도는 동안 하나에 0.1입니다.
- **"요청량"**은 파드가 "최소한 이만큼은 필요하다"고 적어 둔 값이고, 쿠버네티스는 이 합이 서버의 CPU 수를 넘으면 파드를 띄우지 않습니다. 실제 사용량과는 다릅니다.
- ⚠️ **맥의 ARM CPU와 EC2 `t3`의 x86_64 vCPU는 다릅니다.** CPU를 1개 분량으로 줄인 결과도 참고값이며 EC2 성능의 상한·하한은 아닙니다. x86_64용 임베딩 서버 이미지와 실제 인스턴스에서 같은 자료·동시 요청으로 다시 재고, `kubectl top node`와 `kubectl top pods -A`로 자원 사용량을 확인합니다.
- `t3` 계열은 평소에 CPU를 적게 쓰면 여유(CPU 크레딧)가 쌓이고, 바쁠 때 그것을 씁니다. `t3.xlarge`는 평균 40%(1.6 vCPU)까지가 기본 요금입니다. 메뉴 수만 건을 한꺼번에 임베딩하면 몇 시간 동안 CPU를 다 쓰므로, 그때만 추가 요금이 붙거나 잠시 더 큰 유형으로 바꿉니다([운영 문서 3장](../07-운영/01-점검-백업-문제-해결.md#3-서버를-껐다-켤-때)).
- 노코드 도구 Langflow를 더하면 메모리 약 1.3GiB, CPU 요청량 0.1코어, 디스크 약 3.2GB가 늡니다. 더해도 메모리는 16GB의 40%쯤이라 여유가 있습니다([Langflow 문서 7장](../04-에이전트/05-노코드-도구-Langflow.md#7-서버-용량)).
- 이 서버의 한 달 요금과 더 싼 유형(`t3a`·`t4g`·약정)은 [월 비용 계산 2장](../00-개요/04-월-비용-계산.md#2-aws-요금-고정비)에 있습니다.
- **늘려야 하는 때**: `kubectl top node`의 메모리가 70%를 넘는 날이 이어질 때, 게이트웨이 파드가 메모리 한도(2Gi)로 재시작할 때, 새벽 임베딩이 끝나기 전에 다음 작업이 시작될 때.

위 표의 메모리·디스크·속도는 운영 지표·알림 부품 없이 잰 값입니다. 운영 지표·알림(Prometheus·Alertmanager 등)은 이 서버에 CPU 225m·메모리 448MiB의 요청량과 PVC 11GiB(지표는 최대 8GB까지 보관)를 더합니다. 그래서 기본 설치의 CPU 요청량은 약 3.3코어, Langflow까지 넣으면 약 3.4코어입니다. 이 부품들의 실제 사용량은 별도로 재야 하며, [Langfuse는 별도 서버](../07-운영/02-모니터링과-AI-추적.md)에 둡니다.

## 2. 접속과 기본 설정

### 2-1. 내 맥에서 접속하기

내 맥의 터미널에서 실행합니다.

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
mv ~/Downloads/ddalgiro-ai.pem ~/.ssh/
chmod 400 ~/.ssh/ddalgiro-ai.pem
cat >> ~/.ssh/config <<'CONF'

Host ddalgiro-ai
    HostName 203.0.113.20
    User ubuntu
    IdentityFile ~/.ssh/ddalgiro-ai.pem
CONF
ssh ddalgiro-ai
```

- 처음 네 줄은 SSH 폴더를 준비하고 내려받은 열쇠 파일을 옮겨 "나만 읽기"로 바꿉니다. 이렇게 하지 않으면 `ssh`가 권한이 너무 열려 있다며 거절합니다.
- 가운데 묶음은 접속 정보를 `ddalgiro-ai`라는 이름으로 저장합니다. `HostName`에는 1장에서 받은 탄력적 IP를 넣습니다. 이 가이드의 `ssh`·`rsync`·`scp` 명령은 모두 이 이름을 씁니다.
- 마지막 줄에서 `Are you sure you want to continue connecting`이 나오면 `yes`. 프롬프트가 `ubuntu@ip-…:~$`로 바뀌면 서버 안입니다.
- 열쇠 파일의 사본을 딸기로의 비밀값 보관 매체에 둡니다([계정과 비밀값 관리](../../../ddalgiro-guide/docs/00-개요/04-계정과-비밀값-관리.md)).

### 2-2. 업데이트·시간대·디스크 확인

서버에서 실행합니다.

```bash
sudo apt update && sudo apt -y full-upgrade
sudo apt -y install curl rsync openssl
sudo timedatectl set-timezone Asia/Seoul
df -h /
free -h
```

- 첫 두 줄은 보안 업데이트와 이 가이드가 쓰는 도구를 설치합니다.
- 셋째 줄은 시간대를 한국으로 맞춥니다(로그 시각이 한국 시각으로 찍힙니다).
- 넷째 줄의 `Size`가 100G에 가깝고, 다섯째 줄의 `Mem` `total`이 15Gi 안팎이면 1장에서 고른 값대로 만들어진 것입니다.

업데이트 중 커널이 바뀌었으면 `sudo reboot`으로 한 번 다시 켜고 `ssh ddalgiro-ai`로 다시 들어옵니다.

### 2-3. 방화벽은 보안 그룹 하나로

서버 안의 방화벽(`ufw`)은 켜지 않습니다. 우분투 이미지에서 기본으로 꺼져 있고, 바깥을 막는 일은 보안 그룹이 합니다.

```bash
sudo ufw status
```

- `Status: inactive`가 정상입니다.
- 쿠버네티스 관리 포트(6443)와 DB 포트(5432)는 보안 그룹에 넣지 않았으므로 인터넷에서 닿지 않습니다. `kubectl`은 서버에 SSH로 들어와서 씁니다.
- `ufw`를 꼭 켜야 한다면 SSH(22)·웹(80·443)과 함께 파드 대역 `10.42.0.0/16`·서비스 대역 `10.43.0.0/16`을 허용해야 파드끼리 통신이 됩니다(K3s 공식 문서의 안내).

## 3. K3s 설치

서버에서 실행합니다.

```bash
curl -sfL https://get.k3s.io | INSTALL_K3S_VERSION=v1.37.2+k3s1 sh -s - --node-name k3s-ai
```

- K3s를 내려받아 서비스로 등록하고 바로 시작합니다. 서버를 다시 켜도 스스로 뜹니다.
- `--node-name k3s-ai`는 쿠버네티스가 이 서버를 부르는 이름(노드 이름)을 고정합니다. 정하지 않으면 EC2가 붙인 서버 이름(`ip-…`)을 쓰는데, 그 이름이 바뀌면 K3s가 다른 서버로 알고 DB 디스크를 찾지 못합니다.
- `INSTALL_K3S_VERSION`은 [버전 고정표](../00-개요/02-준비물과-정할-값.md#5-버전-고정표)의 값입니다.

`sudo` 없이 `kubectl`을 쓰도록 접속 설정 파일을 내 계정으로 복사합니다.

```bash
mkdir -p ~/.kube
sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config
sudo chown "$USER" ~/.kube/config && chmod 600 ~/.kube/config
echo 'export KUBECONFIG=$HOME/.kube/config' >> ~/.bashrc
source ~/.bashrc
```

- `k3s.yaml`은 클러스터 관리자 권한이 담긴 파일입니다. 본인만 읽을 수 있게(`600`) 둡니다.

### 확인

```bash
kubectl get nodes
kubectl get pods -A
```

- 첫 줄: `k3s-ai`가 `Ready`.
- 둘째 줄: `coredns`·`local-path-provisioner`·`metrics-server`·`traefik`·`svclb-traefik`이 `Running`, `helm-install-traefik…`이 `Completed`. 1~2분 걸릴 수 있습니다.

| 이름 | 하는 일 |
|---|---|
| `traefik` | 바깥 요청을 받아 서비스로 넘기는 문지기 |
| `svclb-traefik` | 서버의 80·443 포트를 Traefik에 이어 줌 |
| `local-path-provisioner` | 파드가 요청한 디스크를 서버의 폴더로 만들어 줌 |
| `coredns` | 클러스터 안의 이름(`postgres.ai-data.svc` 등)을 IP로 바꿔 줌 |

## 4. 저장소를 서버로 보내고 첫 매니페스트 적용

### 4-1. 내 맥에서 저장소 폴더 보내기

```bash
rsync -av --delete --exclude .git --exclude rendered --exclude '.venv' --exclude '__pycache__' --exclude BOX \
  --exclude 'agent/.env' --exclude 'deploy/langfuse/.env' \
  ~/workspace/workspace-vscode/ddalgiro-ai-agent/ ddalgiro-ai:~/ddalgiro-ai-agent/
```

- 저장소 폴더(값 파일 `site.env` 포함)를 서버의 `~/ddalgiro-ai-agent`로 복사합니다. 끝의 `/`를 빼먹지 않습니다.
- 저장소를 고칠 때마다 이 명령을 다시 실행하면 바뀐 파일만 갑니다. `--delete`는 맥에서 지운 파일을 서버에서도 지웁니다.
- `--exclude BOX`: 연구개발계획서 원본은 서버에서 쓰지 않으므로 보내지 않습니다. 서버에서 다시 만드는 `rendered`, 내 맥의 가상환경 `.venv`, 로컬 시험용 `agent/.env`, Langfuse 서버의 비밀값 `deploy/langfuse/.env`도 제외합니다. ⚠️ git의 제외 규칙은 `rsync`에 자동 적용되지 않습니다. 실제 카탈로그·백업·별도 비밀 파일은 저장소 폴더 밖에 둡니다.
- 내 맥의 미커밋 수정과 `site.env`도 함께 보내기 위해 이 방법을 씁니다. `git clone`만 하면 Git에서 제외한 값 파일은 따라가지 않습니다.

### 4-2. 서버에서 값 채우기와 적용

```bash
cd ~/ddalgiro-ai-agent
bash scripts/render.sh
kubectl apply -f rendered/00-namespaces.yaml -f rendered/05-traefik-config.yaml
```

- 둘째 줄은 `site.env`의 값을 `k8s/`의 매니페스트에 채워 `rendered/`에 만듭니다. `만들었습니다: … (12개 파일)`이 나오면 성공입니다.
- 셋째 줄은 네임스페이스 4개를 만들고, Traefik이 요청을 보낸 쪽의 진짜 IP를 보게 설정을 바꿉니다.

### 확인

```bash
kubectl get ns | grep ai-
sleep 30
kubectl -n kube-system get svc traefik -o jsonpath='{.spec.externalTrafficPolicy}{"\n"}'
```

- 첫 줄: `ai-app`·`ai-data`·`ai-llm`·`ai-observe` 네 줄.
- 마지막 줄: `Local`. (`Cluster`가 나오면 Traefik이 다시 배포되는 중입니다. 잠시 뒤 다시 봅니다.)

## 5. 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| `ssh`가 시간 초과 | 보안 그룹의 22 규칙에 적은 IP가 지금 내 공인 IP와 다릅니다 |
| `ssh`가 `Permission denied (publickey)` | 열쇠 파일이 다르거나 계정이 `ubuntu`가 아닙니다. `~/.ssh/config`의 `IdentityFile`·`User`를 확인합니다 |
| `ssh`가 `UNPROTECTED PRIVATE KEY FILE` | 열쇠 파일 권한이 열려 있습니다. `chmod 400 ~/.ssh/ddalgiro-ai.pem` |
| `kubectl`이 `permission denied … k3s.yaml` | 3장의 접속 설정 복사를 안 했거나 새 터미널에서 `KUBECONFIG`가 없는 경우. `echo $KUBECONFIG`로 확인 |
| 파드가 `Pending`에서 멈춤 | `kubectl describe pod <이름> -n <네임스페이스>`의 맨 아래 Events를 봅니다 |
| 서버가 자주 느려짐 | `t3` 계열은 CPU를 오래 많이 쓰면 추가 요금으로 버팁니다(무제한 모드) |
| K3s를 지우고 다시 하고 싶음 | `/usr/local/bin/k3s-uninstall.sh` — ⚠️ 클러스터의 모든 데이터(DB 포함)가 지워집니다 |

- **`ssh`가 시간 초과**: 내 공인 IP는 <https://checkip.amazonaws.com> 으로 확인하고 EC2 → 보안 그룹 → `ddalgiro-ai-sg` → 인바운드 규칙 편집에서 고칩니다. 인스턴스가 `실행 중`인지, 탄력적 IP가 붙어 있는지도 봅니다.
- **파드가 `Pending`에서 멈춤**: `Insufficient cpu`·`Insufficient memory`면 인스턴스 유형이 `t3.xlarge`(4 vCPU · 16GiB)인지, 디스크 부족이면 `df -h /`를 확인합니다.
- **서버가 자주 느려짐**: EC2 → 인스턴스 → 모니터링에서 CPU 크레딧을 보고, 계속 바닥이면 `m` 계열 같은 유형으로 바꿉니다(중지 → 인스턴스 유형 변경 → 시작).
